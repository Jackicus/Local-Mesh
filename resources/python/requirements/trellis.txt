# A static walk of `import trellis` leaves exactly these module-level third-party
# imports: PIL, easydict, numpy, open3d, plyfile, rembg, torch, torchvision,
# tqdm, transformers, utils3d. `open3d` comes in only through the *text*-to-3D
# pipeline's type annotations and is satisfied by ../shims/open3d rather than a
# 400 MB wheel; `kaolin` (one shape-assertion helper inside FlexiCubes) is
# satisfied by ../shims/kaolin. spconv and xformers are imported lazily inside
# the sparse conv / attention modules and are real installs.
#
# Deliberately absent: nvdiffrast, xatlas, pyvista, pymeshfix, igraph (all only
# reached through trellis.utils.postprocessing_utils, which the backend never
# imports), diffoctreerast / diff_gaussian_rasterization (renderers, behind a
# lazy __getattr__), flash-attn (no reliable wheel; ATTN_BACKEND=xformers).
#
# torch / torchvision are installed separately by the main process; the generated
# ~/.local-mesh/constraints.txt pins them during this install so that resolving
# xformers picks the build matching the torch already on disk instead of pulling
# a different torch. xformers is therefore left UNPINNED on purpose — its
# `torch==x.y.z` requirement plus that constraint does the version matching.
