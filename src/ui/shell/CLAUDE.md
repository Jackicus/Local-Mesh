# shell/

The window frame (top bar, dock, window controls, overlay mount) — kept flat on purpose. The top bar is a drag region, so clickable children need `-webkit-app-region: no-drag`.

`BottomDock.tsx` hosts the logs (`views/Logs/LogsPanel`) as an overlay pinned to the bottom of the content area — a resizable panel while open and nothing at all while closed, state in `dockStore.bottom`, toggled from the Logs footer nav item or `Ctrl/Cmd + J`. It overlays rather than shrinks the content so full-bleed views keep their height; `Shell.tsx` publishes its height as `--bottomdock-height` (0 when closed) for the floating plates in Generate and Pipelines. Unseen errors show as a quiet count on the LeftDock's Logs item.

`EngineItem.tsx` sits at the top of the LeftDock footer, above Logs, and is silent unless the python worker has something worth saying: it renders `null` while the worker is stopped or idle with nothing loaded, because that is its normal resting state and "stopped" read as a fault. Working (starting/loading/generating/processing/unloading) gets a spinner and a plain line — "Getting ready…", "Working…", "Finishing up…" — with the model name as a quiet second line; a loaded but idle model gets "<Model> ready"; a worker error leads with "Something went wrong" and keeps the raw message as the second line and the `title`. No VRAM meter, device/precision, idle countdown, Unload or Stop — those are expert plumbing and live in Settings.
